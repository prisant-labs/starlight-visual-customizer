**A free visual theme editor for Starlight: restyle colors, fonts, layout and components on real Starlight pages, then export one CSS file.**

**[Open the studio](https://projects.prisantlabs.com/starlight-visual-customizer/studio/)** · [See the product page](https://projects.prisantlabs.com/starlight-visual-customizer/) · No account, nothing to install

## Why this exists

Starlight gives you a polished docs site in minutes. Making it look like *your* product takes longer. You read up on its CSS custom properties, guess at selectors, rebuild, and then check dark mode separately.

Starlight's built-in color theme editor sets an accent color and a gray. This studio covers the rest: typography, layout, the header, the sidebar, code blocks and the common components. You see every change on real Starlight pages as you make it. When the theme looks right, you take home one CSS file and the exact steps to apply it.

## Who it's for

- **Starlight site owners** who want their docs to match their brand, without learning Starlight's CSS first.
- **Technical writers** who want to restyle a docs site without waiting for a front-end developer.
- **Developers who work with coding agents.** The export includes numbered steps that an agent can follow to apply the theme for you.
- **Theme authors** who want to start a theme visually, then hand-tune the exported CSS.

## From first idea to finished theme

### 1. Start from a preset

Pick one of nine presets, from Starlight's own default look to Editorial Serif and High Contrast Mono. Every value stays editable, so a preset is a starting point rather than a commitment.

### 2. Design on real pages

Shape the whole look with 78 controls in 11 groups. They cover colors, typography, layout, the header, the sidebar, the table of contents, content, components, code, the footer and page options. Each change appears at once on four sample pages: a style guide, a long document, a landing page and the 404 page.

Not sure which control styles something? Turn on **Inspect** and click it on the page, and the studio opens the controls that style it. Want a different navigation? The **Structure** editor lets you drag pages and groups into a new sidebar.

> **Under the hood:** the preview is an actual Starlight 0.42.4 build running in a frame, not a mockup. Your edits go into a stylesheet that the studio adopts into each preview page, so the page restyles without a reload. Colors run through Starlight's own palette algorithm, which tunes the lightness of each color role.

### 3. Check it before you ship

**Split** view shows the same page in light mode and dark mode, side by side, from one theme. The contrast check above the preview tests the main text color pairs in both modes. It uses WCAG AA by default, or AAA if you raise the floor. It flags a failing pair the moment you create one. Device widths run from a 390-pixel phone to a 2560-pixel ultra-wide screen.

![Split view: the same page in light mode and dark mode, side by side](https://github.com/prisant-labs/starlight-visual-customizer/raw/v0.1.0/docs/studio-split.png)

> **Under the hood:** each device width is a real viewport width, so Starlight's own responsive layout applies. The studio then scales the frame down to fit your window.

### 4. Export a theme you own

One click gives you everything you need:

| File | What it holds |
|---|---|
| `theme.css` | Only the values that differ from Starlight's defaults, as plain CSS |
| `APPLY-THEME.md` | Numbered steps to apply the theme, for you or your coding agent |
| `state.json` | Your settings, so you can import the theme later and keep editing |
| A PNG screenshot | The current page, for a design review or a pull request |

Applying a theme takes a few minutes, and there is no plugin to install:

1. Copy `theme.css` into `src/styles/` in your project.
2. Add it as the **last** entry of Starlight's `customCss` option.
3. If you picked a web font, install the package that `APPLY-THEME.md` names, such as `@fontsource-variable/inter`.
4. Rebuild your site. A running `astro dev` server picks up the change on its own.

```js
// astro.config.mjs
starlight({
  title: 'My Docs',
  customCss: [
    // ...any stylesheets you already have
    './src/styles/theme.css', // last, so the theme wins any tie
  ],
}),
```

If you rebuilt the sidebar in the Structure editor, `APPLY-THEME.md` also gives you the new `sidebar` array to paste in.

The exported files are yours to use however you like, and no attribution is required. `theme.css` and `APPLY-THEME.md` each carry one line that links back to the studio, and you are free to delete it.

> **Under the hood:** `theme.css` is deliberately unlayered, so its place at the end of `customCss` decides every tie with another stylesheet. The export is deterministic: the same theme always produces the same file, which keeps diffs in your repository small. A round-trip test applies real exports to a freshly created Starlight site and compares the computed styles with the studio's preview. The steps are tested to reproduce what you saw, not only to read well.

### 5. Share it with a link

Copy a share link, and anyone who opens it sees your exact theme on the page you were viewing. If they already have a theme of their own saved, the studio asks before replacing it. Every change is one undo step, so trying someone else's theme is safe.

> **Under the hood:** the whole theme travels in the link's `#svc=` fragment. Browsers never send a URL fragment to a server, and the studio removes it from the address bar once it has read it. A theme that arrives from a link or an imported file is checked against the controls before it reaches an export. So a crafted link cannot slip code into `APPLY-THEME.md` or extra rules into `theme.css`. Its sidebar can only link to web, mail or relative addresses.

## Private by design

The studio has no backend, no account and no analytics. Your theme stays in your browser until you export or share it. The only outside request the studio makes loads preview web fonts from jsDelivr.

## Built to be trusted

- **273 unit tests** cover the CSS and `APPLY-THEME.md` generators, share-link decoding, the checks on outside themes, sidebar-link safety, color math, and undo and redo.
- **13 browser suites** cover every control's effect, Inspect, the Structure editor, share links and the PNG export. Six of them also run on Firefox and WebKit.
- **A round-trip test** shows that an export reproduces the preview on a fresh Starlight site.
- **Golden files** pin the exact export output, so an unintended change fails a test.

The project is open source under the MIT license.

## Known limits

- **It is built for Starlight 0.42.4.** Starlight is pre-1.0, so a later release can change markup that some styles rely on. `APPLY-THEME.md` names the version it was built for and tells your agent to stop on a mismatch.
- **Some settings only take effect at build time.** Syntax-highlighting themes and a few page options cannot change live. The preview approximates them, and `APPLY-THEME.md` lists the config changes to make.
- **The PNG screenshot is drawn in the browser.** Long pages can take 30 seconds or more, and a few effects such as `backdrop-filter` may be missing. For a pixel-exact image, use your browser's own screenshot tool.
- **Safari itself is untested.** The WebKit tests run in Playwright's build of the engine on Windows, not in Apple's Safari. Those runs found one bug before release: in Split view, the dark side could miss an edit. This release includes the fix, and a browser test now checks it on every engine.
